# Рабочее место диспетчера: новая структура интерфейса

## Задача
Сделать текущую функциональность понятным продуктом: убрать технический шум, объединить связанные действия, привести страницы к одной сетке и визуальному языку Билайна. Правила организаторов, маршрутизация, права доступа, факты выполнения и утверждение плана сохраняются.

## Согласованное направление
Единая оболочка приложения: компактная верхняя панель и боковая навигация. На узких экранах навигация открывается бургером; на широких основные разделы видны постоянно. Альтернативы: оставить верхние вкладки (меньше изменений, хуже помещаются разделы и настройки); объединить всё в один экран (меньше переходов, слишком высокая плотность информации).

Верхняя панель: бренд, выбор района, текущий режим распределения, профиль справа. Убираются отдельная плашка «Район данных», адрес сервера, дублирование района и роли, служебные номера версии в основных показателях. Версия остаётся в истории и диагностике.

Профиль: имя, роль, управление доступом сотрудников при существующих правах, выход. Общие настройки района отделены от персонального профиля: доступны через режим работы рядом с районом. Режимы автопилота и учёта фактов объясняются одной короткой строкой и сохраняются явным действием. Демо-инструменты и диагностика доступны отдельно в меню, не занимают рабочие страницы. Права доступа не расширяются.

## Рабочие разделы
1. **План дня** — стартовая страница. Карта, расписание и поиск заявки. Компактные показатели: назначено, требует назначения, инженеров на линии. Действия: добавить заявку, обновить статус, рассчитать изменения при необходимости. Важные сообщения о неактуальном плане сохраняются рядом с действием.
2. **Заявки и изменения** — поступившие заявки, заявки без исполнителя и явная кнопка расчёта. Порядок: событие/очередь → варианты → изменения → применить. Настройки и запуск симуляции убираются из этого потока. Последний применённый план показывается компактно. Рекомендация появляется только по запросу к ИИ, как согласовано ранее.
3. **Бригады** — состояние сотрудников, подтверждение выполнения и запись фактов; GPS становится соседним представлением внутри раздела. Основной путь: выбрать инженера → указать событие → сохранить → получить следующее действие. Исправления прошлых фактов доступны отдельно. Состав и оборудование остаются отдельной страницей подготовки дня, доступной отсюда и в меню.
4. **Контроль дня** — конкретные заявки/маршруты, требующие проверки, и действия по ним. Убираются декоративные кольца, пустая карточка неисчисляемой поломки транспорта, версии модели, количество прогонов, условные потери и дробное «число клиентов». Ожидаемое значение не округляется и не выдаётся за фактический счётчик: в рабочем представлении используются отдельные заявки и реальные количества записей. Прогнозы честно обозначаются как оценки. Точные численные модельные показатели, источники и допущения остаются в техническом представлении.
5. **История** — события, утверждения и решения, с поиском и фильтром. Без повторяющихся вводных абзацев.

## Визуальные правила
Белый/светло-серый фон, чёрный текст, жёлтый для основного действия и активной навигации. Единые размеры полей, кнопок, заголовков, радиусы и отступы. Одна главная кнопка на этап, вторичные действия спокойнее. Предупреждения — только если они влияют на решение; успешная операция — короткий встроенный статус вместо лишней плашки. Ошибки, устаревшие данные, неназначенные заявки, превышение реакции аварии и необходимость клиентской коммуникации не прячутся. Вложенные раскрытия сокращаются. Диалоги используются только для действительно отдельного действия, а не для чтения обычных показателей.

## Соседние страницы
Общая оболочка и согласованные отступы для подготовки бригад, управления доступом, входа и страницы инженера. Мобильный сценарий инженера, геолокация, подтверждение диспетчером, CSRF и ограничения ролей остаются работоспособными.

## Реализация и проверка
Оболочка и навигация выделяются в общий модуль; существующие обработчики и API сохраняются по возможности. Перенос элементов сопровождается проверкой принадлежности полей формам, фокуса, клавиатуры, переключения района, состояния незавершённых операций и мобильного меню. Технические данные не скрываются случайным CSS: рабочее и техническое представления имеют явные места и назначение.

Проверить: ручной день; автопилот; запись факта с переходом к пересчёту; подтверждение выполнения; новая заявка и авария; сравнение/ИИ/применение; отмена и потеря назначения; устаревшая версия; GPS без данных и с данными; смена района; права администратора и инженера; узкий экран. Дополнить существующие UI/HTTP тесты и выполнить scripts/check.sh. Просмотреть реальные страницы в браузере на широком и узком экранах, сохранить снимки.

## Уточнения после проверки пользователем
Убрать техническую вкладку, повторяющиеся географические подписи и нижние раскрывающиеся блоки плана. Форма события постоянно открыта. История плана получает широкий селектор с коротким названием текущей версии. Режим распределения переключается сразу в шапке с сохранёнными порогами; ошибка сохранения возвращает действующее значение, черновик порогов сохраняется. Демонстрация разделена на поток заявок, учебный прогноз и GPS. Поля одной высоты, профиль с геометрически центрированной стрелкой. В сводке прогноза — целое количество визитов/бригад с индивидуальным риском ≥20%; это порог внимания интерфейса, не норматив компании и не ожидаемое число нарушений. При неполных оценках показывать отсутствие подробной оценки.

## Второе уточнение по результатам использования
Район и режим имеют одинаковые селекторы без подписи «Район». Профиль — круглая кнопка, имя и роль в строке меню. Карточка заявки содержит только сведения для принятия решения; JSON, происхождение координат и доказательства допустимости скрыты из рабочей карточки. Приблизительный адрес отмечается явно. Выделение расписания ограничено внутренней областью блока. Форма события занимает всю ширину и группирует тип/время, адрес, работу/оборудование и клиентское окно. Фильтры истории сгруппированы в отдельные поля. Состав бригад встроен в общую оболочку рядом с GPS; черновик сохраняется между вкладками, регион заблокирован при несохранённых правках. Физический остаток оборудования показан в подразделе состава; закреплённые работы убраны с экрана статусов.

## Day-control briefing
- Extend the accepted compact AI-card pattern: explicit “Объяснить с ИИ” button, up to three verified findings, one next action, no expanding details or automatic plan changes.
- The existing YandexGPT configuration selects emphasis from aggregate findings. Names, addresses and GPS stay local; numbers and actionable wording come from verified dashboard data. Missing forecast data is not described as zero risk. Mandatory unassigned/stale/equipment findings cannot be omitted by the model.
- Use a bounded server-side snapshot cache per region. Summary requests reference a displayed snapshot and plan version; changed plans/demo runs invalidate the result. No risk recomputation or external call under the planner lock. Shared LLM budget/cache applies; fallback is clearly labelled.
- Refresh toolbar uses normal document flow so timeout/error messages cannot cover buttons. Summary clears on refresh, plan changes and demo switch.
