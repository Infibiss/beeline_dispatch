# Интеграция приложения инженера и уточнений организаторов — 22.09.2026

Пользователь разрешил объединить dev/maxim с main, исправить несоответствия, проверить интерфейс, показать результат и отправить main в репозиторий. Слияние готовится в отдельном worktree; рабочие состояния не заменяются тестовыми.

## Принятые решения

- Сохранить утренние модели бригад и сравнение до применения, новые дневные objectives/recommendation и защиту короткого результата Hybrid. Перенести мобильное приложение, аккаунты, GPS, показатели рисков и групповую недоступность.
- Передачу GPS авторизовать по отдельному короткому снимку состава, без ожидания долгого lock оптимизации. Обновление состава должно отзывать доступ удалённого инженера. GPS по-прежнему не закрывает работы и не утверждает планы.
- Инженер сообщает о завершении; диспетчер подтверждает. Промежуточный факт `completion_pending` освобождает инженера по заявленному времени, защищает заявку от повторного назначения и резервирует заявленный расход. Подтверждение исправляет тот же факт на completed с аудитом, сохраняя фактическое время; не удваивает расход и не ломает последующие факты. Уточнение обязательно содержит причину. Окончательно закрытых заявок в остаточном плане нет.
- Обычная новая заявка добавляется только в свободный интервал: старые владельцы, порядок и начало работ сохраняются. Авария допускает перестройку остатка дня, но никогда не прерывает начатую работу. Разрешение перенаправить касается ещё не начатого выезда.
- Для новой аварии 120 минут от поступления до начала работы — явно обозначенный ориентир реакции, не новый жёсткий норматив и не причина скрыто отбросить далёкую аварию. Существующие 80 минут работ + рассчитанная дорога сохраняются. Превышение показывается диспетчеру.
- Регион = исходный CSV. Внутри региона поездки Москва ↔ область допустимы; запрет по городу старта не вводится. Рациональность поддерживается стоимостью дороги; повторные дальние перемещения проверяются отдельно, без выдуманного жёсткого запрета.
- Окна исходных данных сохраняются. Модель поддерживает произвольные окна для разрешённых экспериментов, не меняет их автоматически. Фиксированного предела устройств для пешехода/велосипедиста нет; проверяется фактически выданный запас.
