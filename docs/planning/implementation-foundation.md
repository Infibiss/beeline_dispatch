# Implementation Plan: импорт, проверка, baseline и OR-Tools

**Goal:** Получить воспроизводимый расчет первого плана дня, сравнение baseline/OR-Tools, проверенные маршруты и ведомости выдачи.

**Architecture:** Python-пакет с независимыми моделями, импортом, TravelProvider, валидатором и интерфейсом Solver. Решение каждого алгоритма проверяется независимо и приводится к одному формату. CLI сохраняет JSON и автономный HTML-отчет; ALNS позже заменит адаптер OR-Tools.

**Tech Stack:** Python 3.11+, Pydantic 2, OR-Tools 9, pytest. Без внешних сервисов для малых тестовых сценариев; синтетическая офлайн-география явно разрешена пользователем; реальные координаты следующим этапом.

Пользователь поручил выполнить оба этапа сейчас, контракт с сокомандником отложен. Работа в ветке `codex/routing-foundation`, исходные материалы и `.env` не изменяются. Нет существующего кода/тестов для регрессионного baseline. Коммиты и публикация данных не входят в этот запуск.

## Файлы и контракт

- `src/field_router/models.py`: Request, Engineer, TimeWindow, Equipment, Scenario, Visit, Route, Plan; минуты от начала дня, метры, координаты отдельно.
- `src/field_router/importer.py`: строгий CP1251/UTF-8 CSV импорт с диагностикой строк, офисом и сохранением источника, запрет контрольных данных в CLI подготовки.
- `config/demo.json`: версия, seed, 15 инженеров, смены, распределение навыков/транспорта, нормативы, синтетические потребности, параметры приближения поездок.
- `src/field_router/scenario.py`: обогащение синтетических CSV конфигурацией, происхождение полей, отдельная карта координат или явно выбранная синтетическая география.
- `src/field_router/travel.py`: TravelProvider и матрицы по транспорту; контроль неотрицательных расстояний/времени.
- `src/field_router/validation.py`: независимая проверка назначений, навыков, транспорта, зоны, поездок, окон, окончания смены, устройств, метрик.
- `src/field_router/planning.py`: построение раннего допустимого расписания из последовательностей, объяснения и общие метрики.
- `src/field_router/solvers/base.py`, `baseline.py`, `ortools_solver.py`: контракт solve(scenario, travel, time_limit_seconds) -> Plan, входы одинаковы.
- `src/field_router/report.py`: HTML из общего JSON результата; экранирование исходного текста, расписания/ведомости/причины, честная маркировка синтетических оценок.
- `src/field_router/cli.py`: inspect, prepare, solve, compare; явные ошибки, артефакты результата, команда запуска.
- `tests/`: небольшой набор предметных проверок, реальные три CSV и контрпример, где оптимизация улучшает baseline.

## Границы текущей поставки

Перепланирование по событиям, история публикаций, GPS, LLM/ML и полноценный React-интерфейс не входят в эти два этапа. Модель остатков оборудования проверяется, но динамика расходования по событиям будет следующим этапом. Несколько окон поддерживаются моделями и планировщиками; исходные CSV имеют одно окно. Импорт не пытается восстановить фактические характеристики инженеров из контрольных назначений.

## Критерии завершения

Оба алгоритма возвращают проверяемый общий Plan, назначения и неназначения покрывают вход без потерь, нарушения обязательных ограничений блокируют выдачу результата. Результат сравнения имеет одинаковые данные/параметры/TravelProvider; время поиска и статус показаны. Положительный эффект OR-Tools подтвержден контролируемым контрпримером, а фактические результаты исходных наборов приводятся без обещания математического оптимума. Запуск воспроизводим из README; незаданные источники географии не заменяются скрытыми координатами.

Результат: [фактический отчет проверки](foundation-validation.md), [контракт](solver-contract.md), [запуск](../../README.md). Все пункты текущей поставки закрыты; последующие этапы продукта остаются в общем плане.
