# Пополнение оборудования в течение дня (опционально, не подключено)

Ветка `feature/equipment-replenishment`, от `feature/alns-v2-research`. Затронут только внутренний пакет `src/field_router/_alns`. Адаптер, приложение и OR-Tools не менялись. Приложение склады не передаёт, поэтому поведение прежнее.

## Модель

- `Instance.depots: list[Depot]` — склады с временем загрузки `service` (по умолчанию 15 мин). Узлы складов идут после заявок: `E+N..E+N+D-1`. Матрицы должны включать эти строки и столбцы.
- Пополнение действует только для инженера с известным запасом (`stock` не `None`), и только если заданы склады.
- Правило: инженер заезжает на ближайший по времени склад непосредственно перед первой заявкой, на которую не хватает оборудования, и загружается до утреннего запаса. Заезд — часть плеча к этой заявке:
  - `RouteEval.legs[k] = (минуты с загрузкой, км, склад, минуты в пути)`;
  - время и км заезда учитываются в окнах, смене, `travel_minutes`, `distance_m` и в точном расписании профилей (`stable_starts(..., legs=...)`);
  - `schedule()` отмечает заезд полем `reload_depot`.
- Вставка для таких инженеров перебирает позиции с полным пересчётом маршрута: O(n²) вместо O(n), потому что точки заезда сдвигаются вместе с последовательностью.

## Проверки

- `tests/test_alns_replenishment.py`:
  - без складов запас остаётся жёстким ограничением маршрута;
  - заезд ставится перед нужной заявкой, время и км считаются верно;
  - заезд не нарушает окна и смену;
  - вставка сама выбирает порядок, при котором заезд допустим;
  - на задаче «4 заявки по роутеру, запас 1» решатель без склада выполняет 1 заявку, со складом — все 4.
- Без складов остаётся прежний код расписания (`legs is None`). Число итераций ALNS за 3 с совпадает с `feature/alns-v2-research` в пределах шума: 3200–3343 против 3200–3222 на синтетической задаче 60×8.

## Что нужно, чтобы подключить

1. **Адаптер** `solvers/alns_solver.py`: передать склады региона в `Instance(depots=...)` и добавить их точки в матрицы `road_travel`.
2. **Экспорт плана:** показывать заезд на склад в маршруте (`reload_depot`, плечо) и в оценке остатков `inventory`: после загрузки остаток снова равен утреннему.
3. **OR-Tools:** пополнения не знает. Для сравнения нужны необязательные узлы-склады с обнулением ёмкости — это отдельная задача.
4. **Ограничения правила:**
   - загрузка всегда до утреннего запаса;
   - часы работы склада не учитываются;
   - заезд только непосредственно перед нехватающей заявкой (ленивое правило). Более ранний заезд «по пути» может оказаться дешевле, но модель его не ищет.
