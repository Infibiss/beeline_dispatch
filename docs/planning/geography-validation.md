# Проверка географии и рабочего места — 18.09.2026

## Что реализовано

Импорт WGS84-координат, Photon с кэшем/ограничением частоты, жесткая проверка города/полного названия улицы/дома, список неоднозначных адресов, отдельные OSRM-профили авто/пешком/велосипед, явный флаг оценки общественного транспорта. Сохраненные матрицы позволяют считать без сети. Подписи запрещают старые матрицы после изменения точек; геометрия связывается с координатами, транспортом и порядком визитов.

Карта/схема, список, карточка и расписание синхронизированы; фильтры по инженеру/неназначенным и текстовый поиск, выбор плана/участка, ведомость оборудования. Полные маршруты сохраняются при фильтре поиска, чтобы не рисовать несуществующие сокращения пути через скрытые заявки. Отчет подписывает пунктир как оценочную последовательность.

## Что проверено

- `.venv/bin/python -m pytest -q`: **77 passed**, три предупреждения SWIG из зависимости OR-Tools; `node --check` без ошибок. Проверена клиентская логика Node.js; новые проверки сопоставления адресов, неоднозначности, чужого города/улицы, кэша, асимметрии, null, округления, подписей, CLI и поврежденной геометрии.
- Экспорт использует нормализованные и проверенные модели, а не первоначальный сырой JSON. Поврежденные данные не публикуются.
- Три рабочих места повторно сформированы на 205 заявках с новым правилом: аварии и подключения одного высшего уровня. OR-Tools назначил 201/205 заявок, из них 114/116 высшего уровня; baseline — 127/205 и 59/116 соответственно. Это условная география, не дорожный результат.
- В браузере проверены переключение baseline/OR-Tools, изменение статуса и причины заявки 74198, поиск, выделение в расписании и карточке, загрузка Leaflet, подложка и выбор географической точки.
- Ветка географической карты проверена на отдельном публичном примере двух точек из документации OSRM. Матрица этого примера искусственная и нужна только для UI-теста; это не результат на материалах хакатона. Этот первоначальный UI-тест предшествовал разрешению пользователя и живой проверке ниже.
- Локальные ресурсы Leaflet и лицензия входят в wheel; JS/CSS библиотеки проверены по официальным SHA-256. Для сборки используется стандартная изоляция build dependencies.
- Независимое ревью выявило и помогло исправить частичное совпадение улиц, старую геометрию при перерасчете, ненормализованный экспорт и падение на неверном формате линии.

Список исходных адресов и неподтвержденных кандидатов: [geography-review.md](geography-review.md); браузерная версия `output/demo/geography-review.html`.

Исправлено ошибочное совпадение по окончанию номера: «6-8» не равно «8», «73 c3» не равно «3», «6/14 c8» не равно «8». Проверяется полный номер. Добавлены шоссе/проезд, буквенные строения и корпус без основного номера. Исходные адреса не изменялись. Две разные постройки с одинаковым адресом остаются неоднозначными.

Живой OSRM проверен на двух сопоставленных точках Востока (74198 и 86160): авто 14/15 минут по направлениям, пешком 130/130, велосипед 40/41. Привязка к дороге не дальше 16.75 м. Ответы трех профилей и отдельная оценка общественного транспорта сохранены в `output/geography/road-smoke.json`. Это проверка подключения, не полный участок; пакет не покрывает исходный сценарий и не может быть использован для его расчета.

## Что остается

Полные дорожные матрицы, геометрия и сквозные планы трех участков ожидают проверенных координат 35 точек. Офис Востока: в CSV «83с4», в кандидатах «83к4»/«83к4с2» — подмена не выполнена, вопрос пользователю задан. Офис Юго-востока также не сопоставлен. Ручное исправление требует координат и источника; заявки не отбрасываются. Этап реальной географии пока не завершен.
