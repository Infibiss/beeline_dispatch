# Билайн · Диспетчер выездных инженеров

Хакатон ЛЦТ 2026, кейс 13, команда 40. Локальное приложение распределяет заявки между инженерами, строит маршруты, учитывает оборудование и предлагает варианты перепланирования. Окончательное решение принимает диспетчер.

**Состояние на 19.09.2026:** работают OR-Tools, дорожная география, три стратегии перепланирования, новые адреса, ручные статусы, поздние факты и история исправлений. LLM, ML, GPS и ALNS пока не подключены. Приложение предназначено для демонстрации и проверки решения; это не многопользовательская производственная система.

## Быстрый запуск после клонирования

Нужны Python 3.11+ и сеть для установки зависимостей. Команды выполняются из корня репозитория. Проверенное окружение — Python 3.11; Node.js нужен только для клиентских тестов, не для запуска приложения.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/python -m field_router.scenario_server data/demo-road/Восток.json --state output/local/east-state.json --port 8766 --time-limit 3
```

Откройте **http://127.0.0.1:8766/**. Сохраненные координаты, дорожные матрицы и начальные маршруты включены в `data/demo-road/`: для расчета и перепланирования ключи и сетевые запросы не нужны. Подложка карты OpenStreetMap загружается из интернета; таблицы и расписание работают без нее.

Чтобы включить **поиск нового адреса**, добавьте к команде `--network`. Тогда введенный адрес отправляется Photon, а координаты выбранной точки — OSRM (`routing.openstreetmap.de`). Существующие адреса доступны и без этого флага.

Для другой зоны замените входной файл на `data/demo-road/Юго-восток.json` или `data/demo-road/Югоцентр.json` и укажите отдельный файл `--state`. Не используйте состояние одного региона с другим исходным планом: существующий файл состояния загружается приоритетно.

Чтобы начать новый эксперимент, остановите сервер (`Ctrl+C`) и задайте **новое имя файла состояния**, например `output/local/east-test-2.json`. Предыдущая история сохранится. Сервер доступен только на локальном компьютере; для общего размещения потребуются отдельные аутентификация и хранилище.

## Как пользоваться окном диспетчера

### 1. «План дня» — действующий план

Выберите инженера или найдите заявку по номеру/адресу. Выбор связывает карточку, карту и расписание. В карточке видны окно, приезд, начало/окончание, дорога, ожидание, оборудование и качество координат. Дорога и работа учитываются отдельно.

Пример: найдите `35675`. В начальном дорожном плане Востока это Трофимова, 24 к2, назначение инженеру 07. Проверьте время и потребность перед внесением события. Для неоднозначного адреса, например `47330`, карточка показывает исходный адрес и принятую приближенную точку.

Ведомость утренней загрузки показывает, сколько устройств выдать каждому инженеру. Старая версия в селекторе — только просмотр истории, не откат. Статические `dispatcher.html`/`report.html` — экспорт; актуальное рабочее состояние находится в приложении на 8766.

### 2. «Перепланирование» — сравнить и утвердить

Пример аварии:

1. Выберите «Аварийная заявка», время **11:50**, адрес по заявке **35675**, работу **70 минут**, **1 роутер**.
2. Решите, разрешать ли перенаправление инженера в пути. Если есть начатая работа, явно включите «Сохранить начатую работу до завершения»; иначе запрос потребует уточнения.
3. Нажмите «Рассчитать варианты». До утверждения действующий план не меняется.
4. Сначала сравните приоритетные назначения, неназначенные и потерянные назначения. Затем — начало аварии, смены исполнителя, переносы, дорогу и число инженеров.
5. Выберите вариант, изучите список «было → станет» и нажмите **«Применить план»**.

| Название в окне | Внутренний профиль | Что улучшает после охвата заявок |
|---|---|---|
| Раньше приоритетные | SLA-first | Сумму времен начала аварий и подключений |
| Меньше изменений | Stable | Смены исполнителя и сдвиги времени |
| Меньше ресурсов | Cost-first | Число инженеров и километры; это не рубли |

Все стратегии сначала стараются сохранить охват приоритетных, затем общий охват. Они могут дать одинаковый план — интерфейс отмечает совпадение. Сортировка меняет только порядок просмотра. Авария не обязательно начинается сразу: жесткий норматив реакции не задан, а оборудование и текущая работа ограничивают выбор.

Для **нового адреса** раскройте соответствующий блок, введите город/улицу/дом, нажмите «Найти точку», выберите результат, проверьте карту и подтвердите расчет дорог. Затем задайте параметры аварии и рассчитайте варианты. Проверочный пример — «Москва, Тверская улица, 7». Добавленная точка не гарантирует назначения: для 70 минут и одного роутера в проверочном расчете назначения не нашлось; выезд на 20 минут без устройств был назначен. Это разные условия эксперимента.

Отмена заявки и недоступность инженера проходят тот же цикл сравнения и утверждения. Начатую работу нельзя молча объявить завершенной: сначала внесите фактическое завершение либо прерывание.

### 3. «Статусы инженеров» — что произошло фактически

Выберите инженера: список заявок фильтруется по нему. Внесите время и статус. Для работы/дороги нужен остаток времени; для прерывания — остаток работы и явный расход устройств, включая нули. При завершении пустой расход означает оставшуюся потребность заявки за вычетом уже записанного расхода.

После «Записать факт» нажмите **«Перейти к пересчёту» → «Рассчитать варианты» → выбрать вариант → «Применить план»**. Просто открытие вкладки пересчет не запускает.

Пример позднего сообщения: состояние уже 11:50, а инженер 01 сообщил о завершении `33527` в 10:20. Включите «Сообщение пришло с задержкой», выберите его историческую заявку и укажите 10:20. Часы состояния останутся 11:50. Для исправления выберите эту запись в поле «Запись», измените время на 10:25 и укажите причину. Предыдущая запись останется в истории исправлений. Пример применим к исходному дорожному плану Востока; после других изменений сверяйтесь с историей назначений.

Доступны два режима учета:

- **Демо:** инженеры без фактов моделируются по расписанию. Инженер, для которого уже есть ручной факт, требует дальнейших сообщений; «Работает» не завершается по часам.
- **Ручной:** инженер без фактического статуса недоступен для новых назначений. Сначала внесите доступность и местоположение, затем пересчитайте план.

Несовместимые переходы, повторное завершение, перерасход устройств и устаревшие версии отклоняются. Исправление не может менять инженера записи; несколько фактов одного инженера в одну минуту пока не поддерживаются. Подробная [инструкция](docs/planning/facts-and-addresses-guide.md).

## Текущие допущения и вопросы

| Принято сейчас | Что надо уточнить / заменить |
|---|---|
| 1 бригада = 1 инженер; инженеры синтетические, по 15 на зону | Организаторский справочник: смены, навыки, транспорт, фактические запасы |
| Аварии и новые подключения равноприоритетны, остальные заявки — после них | Подтвердить правило приоритета; нужен ли жесткий срок реакции на аварию |
| Для глобальной проблемы временно 80 минут работы; окно и норматив — разные вещи | Проверить нормативы и исключения по типам работ |
| Возврат в офис в конце дня не обязателен, сверхурочная работа автоматически не добавляется | Нужны ли возврат, перерывы и разрешение переработки |
| Запас выдается утром под план; списание при завершении, частичный расход при прерывании задается явно | Пополнение, передача устройств между инженерами, обязательный резерв на аварии |
| Пользователь разрешил 11 приблизительных координат | Уточнить корпус/строение, когда появятся надежные координаты; [список](docs/planning/accepted-approximate-addresses.md) |
| Общественный транспорт = автомобильная длина / 18 км/ч + 7 минут; актуальных пробок нет | Реальные маршруты/расписания транспорта и модель дорожного времени |
| Дороги OSRM, поиск Photon; максимум 100 точек в одной матрице | Локальный/коммерческий провайдер и разбиение больших наборов |
| Положение задается вручную; без свежего факта нельзя точно перенаправить инженера на дорожном маршруте | GPS и интеграция с приложением инженера |
| Последний остаток работы резервируется заново от времени пересчета | ML-прогноз длительности и отклонений; сейчас это консервативное правило |
| Стоимость показана ресурсами, SLA-first — названием стратегии | Денежные ставки, штрафы, договорный SLA |

Все решения и их история: [реестр допущений](docs/planning/assumptions-register.md). Старые документы в `docs/planning/` описывают этапы разработки; этот README отражает текущее состояние.

## Что осталось

1. **Выбрать и подключить LLM для объяснений.** Кандидаты: YandexGPT Lite/Pro, GigaChat 2 Pro, GPT-5.4 Mini. До выбора пользователя внешних LLM-вызовов нет. Модель должна объяснять проверенные факты, без изменения и утверждения плана; [контракт](docs/planning/llm-explanation-contract.md).
2. **Подключить ALNS сокомандника** через общий контракт и сравнить с baseline/OR-Tools на одинаковых данных и ограничениях.
3. **ML-слой:** длительность/риск задержки и проверка качества на отложенных данных. Исторических фактов пока нет; происхождение будущей синтетики надо явно обозначать.
4. **Интеграции:** реальный справочник, GPS/события, приложение инженера, согласованные правила оборудования и транспорта.
5. **Подготовка к эксплуатации:** общее хранилище, авторизация, многопользовательская работа, мониторинг, среда размещения и CD. Затем финальная демонстрация и презентация хакатона.

## Тесты и CI

```sh
.venv/bin/python -m pytest -q
# Полный набор проверок CI, нужен Node.js:
PATH="$PWD/.venv/bin:$PATH" sh scripts/check.sh
```

Тесты проверяют ограничения маршрутов и оборудование, три стратегии, отмены/аварии, факты и исправления, атомарность сохранения, устаревшие версии, API, клиентские преобразования и пригодность сохраненных дорожных демо. Photon/OSRM в автотестах заменены контролируемыми ответами; реальные внешние сервисы не нужны. Без Node.js клиентские тесты локально пропускаются; в CI Node устанавливается обязательно.

[`.sourcecraft/ci.yaml`](.sourcecraft/ci.yaml) запускает проверки на push в `main` и запрос на слияние в `main`: Python 3.11, фиксированные зависимости, проверка синтаксиса JS, pytest, сборка wheel и проверка включения ресурсов интерфейса. Сохраняются `test-results.xml` и `dist/`. Конфигурация основана на [документации SourceCraft](https://sourcecraft.dev/portal/docs/ru/sourcecraft/ci-cd-ref/). Если запуск не появляется, проверьте доступность воркеров и квоты проекта в разделе CI/CD. Автоматическое развертывание не настроено: целевой сервер еще не определен.

## Данные, воспроизводимость и структура

- `src/field_router/` — импорт, solver, валидатор, API и интерфейс.
- `config/demo.json` — заменяемые настройки демонстрации.
- `data/Обезличивание/` — предоставленные исходные наборы. В расчетах используются **только синтетические CSV**. Контрольные распределения не используются для обучения, подбора и оценки алгоритма.
- `data/demo-road/` — сохраненные планы/география трех зон. Инженеры синтетические; координаты геокодированы, матрицы дорожные; это не реальные записи выездов. Не содержит пользовательской истории статусов и API-ключей.
- `docs/contracts/` — схемы данных; [контракт solver](docs/planning/solver-contract.md).
- `docs/sources/`, `docs/research/` — разбор ТЗ и QA организаторов; `prompt.txt` — исходные указания и уточнения пользователя.
- `tests/`, `scripts/check.sh`, `.sourcecraft/ci.yaml` — проверки и сборка.
- `output/` — локальные результаты, кэш и состояние; исключены из Git. `.env` также исключен.

Материалы организаторов включены в `data/`. Архив пробок 2013–2015 годов и шаблон презентации не являются зависимостями приложения. [Источники географии и лицензии](docs/planning/geography-providers.md); Leaflet поставляется с файлом лицензии, карты требуют атрибуции OpenStreetMap.

Повторить офлайн-расчет на условной географии:

```sh
.venv/bin/python -m field_router demo --synthetic-geography --time-limit 5
```

Результаты появятся в `output/demo/`. Это отдельный эксперимент: не сравнивайте его километры с дорожными как одинаковые измерения. Экспорт дорожного плана без повторной оптимизации:

```sh
.venv/bin/python -m field_router render data/demo-road/Восток.json --output output/export/Восток
```

Для замены инженеров используйте `prepare --engineers engineers.json`. Формат и команды: `python -m field_router --help`, [контракт solver](docs/planning/solver-contract.md), [схема сценария](docs/contracts/scenario.schema.json). Сохраненные дорожные планы необходимо пересчитать после изменения исходного состава заявок/инженеров.
