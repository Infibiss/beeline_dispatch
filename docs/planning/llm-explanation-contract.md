# LLM: объяснение рассчитанных вариантов

Статус: подключён опциональный адаптер YandexGPT через `.env`. Сравнение вариантов использует выбор акцентов и детерминированный текст; карточка отдельной заявки дополнительно поддерживает короткий текст, написанный моделью.

## Пояснение отдельной заявки

`POST /api/assignment-explanation`: текущая версия, ID заявки и токен запуска демо, если он есть. Доступ диспетчерский, с обычной проверкой CSRF и района. Генерация не удерживает блокировку планирования; устаревший ответ не отображается. Состояние, история, назначения и статусы не записываются.

Модель получает только сформированные сервером факты и список плейсхолдеров. Имена, адреса, ID, координаты, комментарии и сохранённый свободный текст не передаются. Ответ — два или три абзаца со ссылками на основания; важные основания нельзя пропустить. Цифры и персональные значения подставляются на сервере, HTML и неподтверждённые абсолютные утверждения отклоняются. Проверка структуры и запрет отдельных утверждений не гарантируют полную семантическую верность свободного текста: ИИ-пояснение маркируется отдельно, а проверенные основания остаются доступными.

На клиенте пояснение запрашивается автоматически при открытии карточки текущего плана. Серверный кэш использует хэш обезличенного контекста и промпта; локальные значения подставляются заново, поэтому персональные данные в кэше модели не хранятся. Общий лимит вызовов `YANDEX_LLM_MAX_CALLS` не увеличен. При недоступности, отказе проверки или исчерпании лимита показываются проверенные основания без ИИ. Для старого плана и неподтверждённых назначений генерация не выполняется.

Новая автоматическая передача включается отдельно через `YANDEX_ASSIGNMENT_PROSE_ENABLED=1` после подтверждения пользователя; значение по умолчанию — `0`. Без включения ни карточка, ни её API не вызывают модель.

## Граница ответственности

OR-Tools рассчитывает планы; валидатор проверяет окна, смены, навыки, дорогу и оборудование. LLM получает только проверенные показатели и изменения и объясняет их диспетчеру. Она не меняет назначения, не создает события и не утверждает план.

## Вход адаптера

Один запрос на сравнение трех вариантов: версия состояния, идентификатор расчета, время события, тип события, флаги сохранения работы/перенаправления, режим учета и географии. Для каждого кандидата: `id`, `label`, `facts`, `diff`, `emergency`, `unassigned_details`, `duplicate_of`. Это существующие поля результата preview; перед отправкой нужен отдельный список разрешенных полей.

Из diff достаточно локальных псевдонимов заявок/инженеров и времени до/после. Исключить адреса, координаты, имена, свободные комментарии, исходные файлы и ключи. Передать ограничения интерпретации: аварии выше подключений, затем ремонт/дозаказы, норматив реакции не задан, денежные ставки отсутствуют, общественный транспорт оценочный, результат поиска не доказывает оптимальность. Закрепленные работы не включены в метрики остатка дня.

## Выход адаптера

JSON: `summary` (короткое сравнение), `options` (ровно существующие candidate_id, преимущества, компромиссы и ссылки на поля-основания), `cautions` (только ограничения из входа). Рекомендация допустима как условная: «Если важнее меньше изменений, ...». При совпадении планов модель должна сообщить совпадение. Автоматического утверждения нет.

До отображения проверить JSON-схему, идентификаторы, ссылки на исходные показатели и числовые значения; текст выводить как текст, без HTML. JSON-схема сама по себе не гарантирует фактическую верность: нужна проверка утверждений и тестовый набор. Если ответ ошибочен, устарел, превышен таймаут или недоступен API, оставить текущую таблицу и шаблонное объяснение. Отказ LLM не блокирует расчет и утверждение.

Кэшировать по версии/идентификатору расчета, хэшу входа, модели и версии промпта. Не публиковать ответ, если состояние изменилось. Начальные ограничения: один короткий ответ на сравнение, таймаут и предел выходных токенов в конфигурации; точные значения утвердить при подключении.

## Варианты для выбора (официальные документы проверены 19.09.2026)

| Вариант | Основание для рассмотрения |
|---|---|
| YandexGPT Lite; при недостатке качества — Pro | Lite рассчитана на быстрые текстовые задачи и суммаризацию, Pro — на более сложный анализ. Пользователь уже упоминал Yandex Cloud, поэтому это практичный первый кандидат; доступ к AI Studio и биллинг необходимо проверить после выбора. |
| GigaChat 2 Pro | Документация выделяет следование сложным инструкциям и суммаризацию. Идентификатор `GigaChat-2-Pro`; нужны отдельные учетные данные API. |
| OpenAI GPT-5.4 Mini | Поддерживает структурированные ответы. Альтернатива при наличии доступного аккаунта API и биллинга. Не утверждаем, что она лучше на нашем русском наборе без измерений. |

Источники: [Yandex AI Studio](https://aistudio.yandex.ru/en/docs/ai-studio/concepts/generation/), [GigaChat — выбор модели](https://developers.sber.ru/docs/ru/gigachat/guides/selecting-a-model), [OpenAI GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini).

Ни одна модель не протестирована на данных проекта. Дообучение для первой версии не планируется: сначала сравнить точность пересказа, отсутствие выдуманных чисел, задержку и стоимость на одинаковых сохраненных расчетах. Ключ не передавать в чат; после выбора настроить локальное окружение.
