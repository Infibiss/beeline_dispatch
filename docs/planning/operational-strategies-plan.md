# Стратегии рабочего дня — план реализации, 22.09.2026

Пользователь принял предложенную политику: «Меньше изменений», «Быстрее к аварии», «Меньше дороги». Работа в main с сохранением действующих планов.

## Единый контракт

Общий лексикографический префикс: неназначенные аварии → неназначенные аварии/подключения → все неназначенные. Затем:

- Утро (profile=None): число задействованных бригад → метры (прежнее поведение).
- Stable: предотвратимые смены исполнителя → сумма абсолютных сдвигов начала → минуты дороги → метры → бригады.
- Cost: минуты дороги → метры → смены исполнителя → сдвиги → бригады.
- SLA: начало новой аварии (явный focus_request_id) → стабильность → дорога → бригады. При обычном пересчёте без новой аварии цель охватывает только оставшиеся аварийные работы; при отсутствии аварий совпадает со Stable. Подключения не маскируют время реакции на аварию.

Неназначенная целевая авария получает оценку 1441, хуже любого допустимого начала в этом дне. Выбывший инженер не штрафуется как предотвратимое переназначение, но обещанное клиенту время сохраняет значение. Потери ранее назначенных заявок видны отдельно; новая жёсткая защита конкретных ID при равном охвате в этот этап не входит. Нет выдуманных денежных тарифов или послаблений в ограничениях.

## Шаги и проверка

- [x] objectives.py: общий точный компаратор, reference и target helpers. OR-Tools: безопасные веса; если полный суффикс не помещается в целое число, поиск использует точный префикс с диагностикой пропущенных вторичных критериев. Финальное сравнение всегда точное. Hybrid передаёт явную цель аварии обоим решателям.
- [x] ALNS: учёт минут, согласованные вставки/оценки/SP; расписание с ожиданием минимизирует сдвиги для всех дневных профилей, SLA сначала минимизирует целевое начало. None сохраняет прежний утренний поиск.
- [x] Перепланирование: focus не переносится на следующее событие автоматически; общий пул по трём профилям; метрики целей; совпадения определяются полным порядком/временами маршрутов. В API сохраняются три ID, канонический представитель Stable → SLA → Cost.
- [x] Рекомендация сервера: общий охват → реакция на новую аварию при её наличии → стабильность → дорога. ИИ объясняет этот выбор проверенными цифрами; недопустимый выбор отклоняется. Утверждение только диспетчером.
- [x] Интерфейс: одна карточка на уникальный план, перечисление совпавших целей, разница с Stable, сортировка дороги по минутам, одна плашка ИИ до карточек.
- [x] Тесты RED→GREEN: реальный выигрыш минут ценой дополнительного инженера, новая авария вместо суммы подключений, сохранение времени после выбытия инженера, совпадение оценок ALNS/общего компаратора, группировка, приоритеты рекомендации и версии.
- [x] Полный CI-скрипт, сохранение показателей всех альтернатив в сценариях дня, браузерная проверка. Коммит по проверенному результату.

Проверка завершена: 391 тест, JS и wheel; 24 этапа/72 допустимых предложения дня; 12 утренних сравнений, без обещания улучшения каждого запуска. Интерфейс и живой YandexGPT проверены. Подробности — [отчёт](../reviews/operational-strategies.md). Рабочие состояния сохранены.
