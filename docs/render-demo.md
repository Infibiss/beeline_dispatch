# Демо на Render Free

Один Docker Web Service, один экземпляр, без постоянного диска и отдельной базы.
Все вошедшие пользователи работают с одним общим днём в каждом из трёх регионов.
Каждый запуск процесса восстанавливает исходные сценарии; применённые планы,
факты, дополнительные аккаунты и GPS-история при перезапуске пропадают.
Выгрузите нужные результаты до обновления. Локальные состояния в образ не входят.

## Образ

Собирать из корня для Render (linux/amd64):

```sh
docker build --platform linux/amd64 -t field-router-demo .
```

Образ запускается непривилегированным пользователем. Включены три исходных
региона, карта и транспортная модель. Бюджеты: утро 10 секунд, день 3 секунды
на вариант. GPS включён; производительность и память проверяются на Render.
Docker Hub / другое выбранное registry должно хранить образ приватно.

## Render

New → Web Service → Existing Image. Выбрать опубликованный образ и Free.
Health Check Path: `/healthz`. Docker Command оставить пустым.
Внешний HTTPS URL автоматически берётся из `RENDER_EXTERNAL_URL`.
Для собственного домена задать `FIELD_ROUTER_PUBLIC_ORIGIN=https://ваш-домен`.
Произвольные `X-Forwarded-*` не используются для разрешения запросов.

Секреты окружения:

- `FIELD_ROUTER_ADMIN_PASSWORD`: отдельный пароль демо, 12–128 символов. Логин `admin`.
- `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`: существующие настройки LLM.
- `YANDEX_MODEL`: выбранная модель (необязательно).
- `YANDEX_LLM_MAX_CALLS=20`: лимит вызовов на процесс, сбрасывается при перезапуске.

Не помещать `.env`, пароли, ключи registry или deploy hook в образ и Git.
Пароль администратора публичного сервера не печатается в журнал.
Перезапуск сервиса возвращает и начальный пароль из окружения.

## Проверка после размещения

1. `/healthz` отвечает 200 без выдачи данных; `/api/state` без входа отвечает 401.
2. Войти, открыть каждый регион, рассчитать три варианта события и применить один.
3. Проверить запись факта, страницу инженера и объяснение LLM.
4. Перезапустить сервис и убедиться, что восстановился исходный день.
5. Проверить память и время расчётов на бесплатном сервере.

Free засыпает после 15 минут без обращений; холодный старт может занять около
минуты. Это стенд для оценки, не постоянное рабочее хранилище.

## Автоматическое обновление

SourceCraft остаётся основным репозиторием. Workflow `release` для push в main
сначала выполняет `test-and-package`, затем собирает linux/amd64-образ и публикует
единственный тег `docker.io/infibiss/field-router-demo:demo`. Docker Hub webhook
вызывает Render с `imgURL` этого тега. Полный SHA сохранён в OCI-метке
`org.opencontainers.image.revision` и журнале CI. Pull request запускает только `checks`. Доступ CI на запись и
доступ Render только на чтение задаются отдельно. Публикацию из pull request
не включать. Секреты передаются только кубику публикации.

`scripts/deploy_render.py` в CI использует `RENDER_TRIGGER=dockerhub` и секрет
`DOCKERHUB_PUSH_TOKEN` (Read & Write без Delete). Deploy hook хранится в webhook
приватного Docker Hub. Прямое соединение SourceCraft с `api.render.com` завершалось
таймаутом; сохранённый ранее `RENDER_DEPLOY_HOOK` этим workflow не используется.
Успешный CI означает публикацию; доставку webhook проверять в Docker Hub,
а завершение запуска — по статусу Live в Render.

Webhook срабатывает на любой push репозитория, поэтому release публикует только
`demo`, без второго SHA-тега. Не отправлять сюда экспериментальные образы:
это тоже запускает обновление. Старые SHA-теги сохранены для отката.
Для ручного запуска сохранён режим `RENDER_TRIGGER=direct` (по умолчанию):
ему нужны оба секрета и доступ к API Render.

Публичный адрес: https://beeline-field-router-demo.onrender.com.
Логин `admin`, пароль задаётся владельцем в Render, в репозитории его нет.

На первом публичном прогоне подтверждены вход, расчёт трёх вариантов,
ответ YandexGPT и применение плана. Затем запись факта превысила 512 МБ,
и Render перезапустил процесс. Причина: полная таблица транспортных маршрутов
дублировалась в каждой версии истории и копиях транзакции. Теперь сохранённый
вид содержит только переезды своего плана; исходная матрица для оптимизации
сохранена полностью. Регрессионный тест проверяет детализацию нужных переездов,
псевдонимы точек и восстановление полной матрицы из сохранения.

Повторный контейнерный прогон с **0.1 CPU / 512 MiB**: все три района,
три расчёта и применения плана, девять записей фактов и просмотр каждой версии
прошли без OOM. Общий пик cgroup — **445.4 MiB**, после теста — 375.4 MiB.
Расчёт: Восток 17.0 с, Юго-восток 125.8 с, Югоцентр 19.1 с.
Применение: 22–28 с; запись факта: 35–43 с. Это измерения Linux/amd64
контейнера на Mac с эмуляцией, а не гарантия времени на Render.
565 тестов, JavaScript и пакет прошли локально и в SourceCraft.

Исправление памяти проверено на публичном Render: вход, запись факта,
повторный расчёт и утверждение Востока (версия 3), расчёт Юго-востока,
