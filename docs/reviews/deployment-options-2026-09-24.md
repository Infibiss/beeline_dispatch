# Размещение приложения и обновления из SourceCraft

Проверено 24.09.2026 для `main` на `412ad44`. Это оценка вариантов, не выполненный деплой.

## Рекомендация

Для текущего прототипа проще один постоянно работающий сервер/VM с постоянным диском и HTTPS. Автодеплой: push в main → существующие тесты и сборка → публикация новой версии → проверка работоспособности. При неуспешных тестах рабочая версия не обновляется. JSON состояний и SQLite аккаунтов должны жить отдельно от сменяемой версии кода; перед обновлением нужна резервная копия. Перезапуск пока сбрасывает входы и оперативную историю GPS, но сохранённые планы и аккаунты остаются на диске.

Подходит, например, Compute Cloud с постоянным диском: https://yandex.cloud/en/docs/compute/concepts/disk . Конкретный сервер, бюджет и доступ ещё не выбраны; ресурсы не создавались.

## Почему Vercel требует адаптации

Vercel поддерживает Python, поэтому проблема не в языке. Однако текущее приложение — `ThreadingHTTPServer`, а не готовый обработчик Functions/ASGI. Оно использует:

- SQLite для аккаунтов и JSON-файлы состояний;
- память процесса для сессий входа, рассчитанных вариантов и состояния регионов;
- локальные блокировки для последовательного изменения планов;
- фоновые потоки/процесс для GPS;
- CPU-расчёты OR-Tools/ALNS.

Vercel Functions предоставляют файловую систему только для чтения и временный `/tmp`, а не постоянный диск для этих данных. Вызовы могут обслуживаться разными экземплярами: локальные блокировки и память не являются общей базой состояния. Поэтому простое копирование кода или перенаправление SQLite в `/tmp` не обеспечит сохранность и согласованность работы.

Источники:
- https://vercel.com/docs/functions/runtimes
- https://vercel.com/docs/functions/runtimes/python

Варианты при обязательном Vercel:
1. Интерфейс на Vercel, сервер и постоянное хранилище отдельно. Нужна адаптация маршрутов/proxy, cookie и разрешённых origin.
2. Полная адаптация под Functions: внешний storage/DB, общие сессии и варианты, транзакционный контроль версий, иной жизненный цикл GPS и обработчиков. Это отдельная доработка, а не настройка токена.

Даже для обычного VM перед публикацией надо настроить доверенный публичный домен и HTTPS: текущий allowlist рассчитан на localhost/IP. Нельзя просто выключить проверки Host/Origin/CSRF. Заголовки reverse proxy надо доверять только от своего proxy, secure-cookie должна соответствовать внешнему HTTPS.

## SourceCraft → Vercel

Прямая Git-интеграция SourceCraft не заявлена в списке Vercel. Для произвольного Git-провайдера поддерживается Vercel CLI из CI. Следовательно, SourceCraft CI может выполнять deploy после успешных проверок main; зеркало в GitHub для этого не обязательно.

Нужны Vercel-проект и значения `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` в настройках CI (токен хранить секретом). Ключ LLM и другие серверные переменные задаются в окружении сервера, не в клиентском JavaScript и не в репозитории. Секреты в сообщениях присылать не требуется.

Источники:
- https://vercel.com/docs/git
- https://vercel.com/kb/guide/using-vercel-cli-for-custom-workflows
- https://sourcecraft.dev/portal/docs/ru/sourcecraft/concepts/
- https://sourcecraft.dev/portal/docs/ru/sourcecraft/ci-cd-ref/

## Codex / MCP

В текущей сессии подключённых инструментов Vercel нет. Официальный Vercel MCP существует: `https://mcp.vercel.com`, авторизация OAuth. Он позволяет управлять проектами, деплоями и читать логи. Поддержка подключения MCP есть в Codex; в документации Vercel приведён `codex mcp add vercel --url https://mcp.vercel.com` с последующей авторизацией в браузере.

MCP помогает управлять сервисом из Codex, но не заменяет доступ CI и не устраняет архитектурные ограничения хостинга. Для автоматических обновлений работающий Codex не требуется.

Источники:
- https://vercel.com/docs/agent-resources/vercel-mcp
- https://learn.chatgpt.com/docs/extend/mcp?surface=cli

## Что потребуется от пользователя

Сначала выбрать размещение: отдельный сервер для всего приложения либо обязательный Vercel с одним из вариантов адаптации.

Для сервера: адрес/доступ SSH к выделенной VM или выбранный облачный проект и согласованный бюджет создания, домен при наличии, возможность добавить секреты деплоя в SourceCraft.

Для Vercel: аккаунт/проект, OAuth через MCP или CLI для первоначальной настройки и секреты CI для автоматического деплоя; дополнительно выбранное размещение backend/DB в соответствии с архитектурой выше. Один токен сам по себе недостаточен для переноса текущего приложения.
