# Сохранение лучшего плана при продолжении поиска — 22.09.2026

Пользователь одобрил исправление: сначала короткий расчёт, затем улучшение его результата в оставшееся время. Анализ новой ветки выполняется отдельно, без слияния в рабочий main.

**Контракт:** hybrid при бюджете свыше 3 секунд сначала выполняет прежний короткий этап (OR-Tools 40%, ALNS — остаток до 3 секунд). Проверенный лучший план становится начальным решением продолжения ALNS. Возвращается минимум по тому же полному ключу; ухудшение, недопустимый план или ошибка продолжения не теряют сохранённый результат. Общий бюджет один, подготовка/остановка по-прежнему могут добавить небольшие накладные расходы.

Для продолжения уже выполненного отдельного расчёта `HybridSolver.solve` получает необязательный `initial_plan`. Он должен быть допустим для переданных сценария и матриц; иначе ошибка, без молчаливой подмены входных данных. Это исходный план поиска, отдельно от `reference`, задающего клиентские обещания и стабильность. Гарантия относится к фактически переданному/найденному плану, не к сравнению произвольных независимых запусков. Состояние поиска ALNS и весь пул маршрутов между вызовами не сохраняются; сохраняется лучшее расписание.

Файлы: `solvers/selection.py` — этапы и выбор; `tests/test_solver_selection.py` — регрессии; `scripts/check_hybrid_continuation.py` — последовательная проверка на сохранённых регионах; документация и реестр допущений — пределы гарантий.
