# Реальная география и рабочее место диспетчера

**Goal:** Заменить условные точки проверяемыми координатами адресов и подключить связанную карту/расписание/карточку.

**Architecture:** Существующие Scenario/Plan/Solver сохраняются. Отдельный GeographyBundle содержит WGS84, качество/источник координат, четыре транспортные матрицы и геометрию выбранных маршрутов. Сетевые ответы кэшируются; подготовка и расчет разделены. HTML диспетчера принимает тот же проверенный comparison.json.

**Tech Stack:** Python, существующий OR-Tools, Photon/OSRM через заменяемые URL; локальный HTML/JS + Leaflet. Нет нового сервера состояния и внешней базы.

Пользователь поручил выполнить следующие два этапа. Состав карты/расписания уже принят общим планом. Работа продолжается в текущей ветке, без публикации и коммитов. Выбор приблизительного общественного транспорта уточняется отдельно; независимые части можно реализовать сейчас.

## Решения

- Photon на данных OSM: нормализовать написание адреса без изменения исходника; ограничение областью Москвы/ближней области; сохранять кандидатов, принимать только совпавшие дом и улицу; неоднозначное/отсутствующее совпадение блокирует реальный расчет до исправления. Ручные координаты импортируются с источником и признаком проверки.
- Координаты только WGS84, не смешивать с Point(x_km,y_km). Для реального расчета требуется полный набор заявок и стартов; пропавшие координаты не заменять синтетикой.
- OSRM: дорожные матрицы и геометрия с метаданными профиля. Null/ошибки/неполные матрицы блокируют расчет. Профили пешком/велосипед можно подключить отдельно; общественный транспорт без расписаний требует явного допуска оценки.
- Кэш по URL/параметрам, последовательные запросы не чаще 1.1 с, timeout, остановка при ошибках без цикла запросов. Данные открытых адресов из синтетических CSV; .env не нужен.
- Интерфейс: выбор участка/плана/инженера, поиск заявки, карта, временная шкала работы/дороги/ожидания, карточка, неназначенные, ведомость оборудования. Общий выбранный request_id. Цвет инженера постоянен внутри плана. Прямые линии не называть дорожными маршрутами. Источник и качество координат/поездок видны.
- Локальные ресурсы Leaflet; базовые тайлы OSM загружаются по видимой области с атрибуцией. Нет скачивания карты целиком. При отсутствии сети список, расписание, точки и расчетные линии работают; статус подложки явный.

## Задачи и проверки

- [x] 1. `geo_models.py`, `geography.py`, `tests/test_geography.py`: координаты, качество, строгая полнота, отсутствие подмены; нормализация корпуса/строения; повторный адрес один запрос. Тесты сначала падают, затем реализация.
- [x] 2. `geo_http.py`, `geography.py`: кэшируемый Photon-клиент с задержкой и журналом ошибок. Проверить кэш без сети, неоднозначный/чужой дом, границы координат и ручной override.
- [x] 3. `road_travel.py`, `tests/test_road_travel.py`: матрицы OSRM, разные профили, целые минуты/метры, асимметрия, отказ при null, provenance. Приближение отдельным явным флагом.
- [ ] 4. `cli.py`: geocode → geography JSON → real compare; сохранение результатов и геометрии, независимый валидатор, запуск на исходных данных с отчетом качества.
- [x] 5. `dispatcher.py`, `static/dispatcher.js/css`, `tests/test_dispatcher.py`: автономное рабочее место на общем payload; безопасная сериализация и экранирование, состояния пусто/нет карты/неназначено; браузерная проверка связи карты/расписания/карточки и переключений.
- [ ] 6. Независимое ревью, полный pytest, сквозной расчет, проверка браузером. README, реестр допущений, фактические результаты и ограничения.

Команды проверки: `.venv/bin/python -m pytest tests/test_geography.py tests/test_road_travel.py -q`, затем весь набор `.venv/bin/python -m pytest -q`. Финальный HTML проверяется в браузере, включая выбор заявки и смену плана без оставшейся карточки другого плана.


## Фактический статус

Локальная реализация всех компонентов готова. CLI геокодирования/матриц/расчета/экспорта проверен изолированно; дорожный источник и геометрия не подменяются синтетикой. Рабочее место проверено на 205 исходных заявках в офлайн-сценариях и на отдельном публичном примере координат OSRM для ветки Leaflet. Публичный пример служит только проверке интерфейса, не результатом хакатона.

Незавершенная часть пунктов 4 и 6: полные дорожные матрицы и сквозной перерасчет трех наборов после уточнения 35 из 208 точек. Пользователь разрешил Photon и продолжение: геокодирование выполнено, три профиля OSRM проверены на паре реальных точек. Участки не пересчитываются с неполной географией. Подробности и метрики — в geography-validation.md, спорные адреса — в geography-review.md.
